# AI Blocks

## Features

An AI block calls a large language model (LLM) to process a prompt and stores the model's response in the variable context, making it available to subsequent blocks or the document body.

Two providers are currently supported:

- **OpenAI** — services compatible with the OpenAI API (including DeepSeek, Ollama, and other compatible APIs)
- **Anthropic** — the Claude family of models

## Syntax

````markdown
```ai {model: "gpt-4o", output: "summary", temperature: 0.7}
Your prompt here; you can reference the context with {{variables}}
```
````

The block's language identifier must be `ai`. Metadata is written in JSON-style `{key: value}` form after the language identifier.

## Parameters

| Parameter | Required | Default | Description |
|------|------|--------|------|
| `output` | No | None | The variable name to store the result in. If omitted, the result is only printed to the terminal (debug mode) |
| `model` | No | `llm.model` from config | Override the default model, e.g. `gpt-4o-mini` |
| `temperature` | No | `llm.temperature` from config | Override the default temperature, 0-1 |
| `max_tokens` | No | provider default | Override the max output tokens |
| `stream` | No | false | Stream the output; when `true`, the CLI spinner shows generated content in real time (final result is unchanged) |
| `format` | No | None | Structured output: `json` parses to an object, `json-array` enforces an array; parse failure fails the block (raw output included) |
| `prompt` | No | None | Reference `.flow/prompts/<name>.md` as the prompt (v0.6.0 Prompt library); content may be empty, supports `{{variables}}` |
| `conversation` | No | None | Multi-turn conversation tag (v0.6.0). AI blocks with the same name automatically carry prior user/assistant history |
| `retry` | No | 0 | Auto-retry count on failure (exponential backoff: 500ms × attempt). Total runs = 1 + retry |
| `validate` | No | None | Output validation: `json` (valid JSON), `json-array` (JSON array), `non-empty`. Validation failure counts as failure and triggers retry |
| `deliver` | No | None | Output delivery (v0.5.0): `webhook:<url>` POST JSON, or `file:<path>` writes to a file (auto-creates dirs). Delivery failure only warns, does not block |

### About the output Parameter

If `output` is specified, the model's reply is stored in a variable, which later blocks or the document body can reference with `{{variableName}}`. If omitted, the model still runs, but the result is not kept in the context. It is usually recommended to always specify `output`, unless you only want to test connectivity.

### Structured Output (format)

Use `format: "json"` to have the model reply auto-parsed via `JSON.parse` before being stored, so downstream templates can access fields directly:

````markdown
```ai {output: "report", format: "json"}
Return JSON: {"summary": "...", "score": 0-100, "issues": [...]}
{{data}}
```

Score: {{report.score}}　Issues: {{report.issues | len}}
````

- `format: "json"` parses to an object; `format: "json-array"` enforces an array result (errors otherwise)
- On parse failure the block fails; the error message includes a snippet of the raw output (first 200 chars)
- Compatible with `stream: true` (accumulates text first, then parses)
- Compatible with `--cache` (cached `value` is the parsed object, not a string)

### External Prompt Library (prompt)

Since v0.6.0 you can store reusable prompt templates in `.flow/prompts/<name>.md` and reference them with `prompt`:

```bash
# .flow/prompts/sales-analysis.md
You are a sales analyst. Analyze the following data for {{topic}}: {{data}}
Output format requirements: {{format}}
```

````markdown
```ai {output: "analysis", prompt: "sales-analysis", topic: "Q3 regional comparison"}
```
````

- `prompt` is mutually exclusive with inline content; when set, the file content is the prompt (errors if not found)
- `{{variables}}` in the file render as usual; non-content parameters (e.g. `topic`) are injected via `--var` or prior blocks
- Symmetric with the template library (`.flow/templates/`): templates manage document structure, the prompt library manages AI prompts

### Multi-turn Conversation (conversation)

Since v0.6.0, AI blocks sharing the same `conversation` tag form a conversation chain; later blocks carry prior user/assistant history:

````markdown
```ai {output: "analysis", conversation: "report"}
Analyze this financial statement...
```

```ai {output: "followup", conversation: "report"}
Based on the analysis above, what are the risks?
```
````

- History is kept in the context for the execution process; different tags are independent
- Each block appends its user prompt and assistant reply to the history
- **Blocks with `conversation` skip `--cache`** (context differs every time, caching is meaningless)

## Configuration Requirements

AI blocks require an LLM provider and API Key to be configured. See the [Configuration Guide](../02-configuration.md). If no API Key is configured, execution will fail with a prompt to set the environment variable.

## Named Model Presets

If you need to switch between different models or providers within a document, you can predefine multiple named model presets in the config file and reference them by name in AI blocks:

```yaml
# .flow/config.yml
llm:
  provider: openai
  model: gpt-4o
  models:
    fast:
      model: gpt-4o-mini
      temperature: 0.3
    reason:
      provider: openai
      model: deepseek-reasoner
      baseURL: https://api.deepseek.com
```

````markdown
```ai {model: "fast", output: "summary"}
Generate a quick summary
```

```ai {model: "reason", output: "analysis"}
Deep analysis
```
````

Presets override the corresponding fields of the global `llm` config. If a preset switches `provider`, the API Key is automatically read from the corresponding environment variable.

## Combining Multiple Models

Using named model presets, you can call different providers within the same document:

````markdown
```ai {model: "fast", output: "title"}
Generate a title
```

```ai {model: "reason", output: "content"}
Deep analysis: {{title}}
```
````

## Variable Injection

Variables can be injected from the command line at execution time and referenced directly inside AI block content:

```bash
flowmd run doc.md --var topic=AI --var style=formal
```

````markdown
```ai {output: "article"}
Write an article about {{topic}} in a {{style}} tone
```
````

## System Variables

The following system variables are automatically injected into the context and can be referenced in AI block content:

- `{{date}}` — current date (YYYY-MM-DD)
- `{{datetime}}` — current date and time (YYYY-MM-DD HH:mm:ss)
- `{{timestamp}}` — current Unix timestamp

## Examples

### Basic Usage

````markdown
```ai {output: "summary"}
Summarize what FlowMD does in one sentence
```

Summary: {{summary}}
````

### Specifying a Model

````markdown
```ai {model: "gpt-4o-mini", output: "tags"}
Extract keywords from the text below: {{article}}
```
````

### Passing Context with Variables

AI block content can reference variables output by previous blocks:

````markdown
```data {output: "sales_data"}
SELECT product, amount FROM orders
```

```ai {output: "analysis"}
Analyze the sales data below and point out trends and anomalies:
{{sales_data}}
```
````

### Chaining Calls

Multiple AI blocks chained together, each using the output of the previous one:

````markdown
```ai {output: "outline"}
Generate an outline for "Applications of AI in Healthcare"
```

```ai {output: "content"}
Using the outline below, expand it into a full article:
{{outline}}
```
````

### Extracting Facts at Low Temperature

````markdown
```ai {temperature: 0.1, output: "facts"}
Extract only factual information from the text below without adding any commentary:
{{text}}
```
````

### Using a Custom API Base URL (Proxy or Compatible API)

After setting `baseURL` in the config, all AI blocks will use that address:

```bash
export FLOW_LLM_BASE_URL="https://api.example.com/v1"
```

This allows using OpenAI-compatible services such as Ollama, vLLM, and DeepSeek.

## Best Practices

- **Write clear prompts**: state the role, task, output format, and constraints
- **Use meaningful names**: `summary` is much more readable than `x`
- **Break down complex tasks**: several chained AI blocks are more stable and easier to debug than one oversized prompt
- **Lower temperature for fact extraction**: `temperature: 0.1` suits information extraction, while `0.8+` suits creative generation
- **Prefer template blocks for multi-step workflows**: AI replies are raw text; use a template block for the final layout
