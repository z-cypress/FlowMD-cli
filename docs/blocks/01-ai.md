 # AI 块

 ## 功能

 AI 块调用大语言模型（LLM）处理提示词，并将模型返回的结果存入变量上下文，供后续块或文档正文使用。

 当前支持两种提供商：

 - **OpenAI** — 兼容 OpenAI API 的服务（含 DeepSeek、Ollama 等兼容 API）
 - **Anthropic** — Claude 系列模型

 ## 语法

 ````markdown
 ```ai {model: "gpt-4o", output: "summary", temperature: 0.7}
 你的提示词，可以用 {{变量}} 引用上下文
 ```
 ````

 块的语言标识符必须为 `ai`，元数据用 JSON 风格的 `{key: value}` 写在语言标识符后面。

 ## 参数

 | 参数 | 必填 | 默认值 | 说明 |
 |------|------|--------|------|
 | `output` | 否 | 无 | 结果存入的变量名。不指定则只输出到终端（debug 模式） |
 | `model` | 否 | 配置文件的 `llm.model` | 覆盖默认模型，如 `gpt-4o-mini` |
 | `temperature` | 否 | 配置文件的 `llm.temperature` | 覆盖默认温度，0-1 |
 | `max_tokens` | 否 | 提供商默认 | 覆盖最大输出 Token 数 |
 | `stream` | 否 | false | 流式输出，`true` 时 CLI spinner 实时显示生成内容（不影响最终结果） |
 | `format` | 否 | 无 | 结构化输出：`json` 自动解析为对象，`json-array` 强制为数组；解析失败块报错（含原始输出） |
 | `prompt` | 否 | 无 | 引用 `.flow/prompts/<name>.md` 作为提示词（v0.6.0 Prompt 库），内容可为空，支持 `{{变量}}` 注入 |
 | `conversation` | 否 | 无 | 多轮对话标签（v0.6.0）。同名 AI 块自动携带前序 user/assistant 历史，形成连续对话 |
 | `retry` | 否 | 0 | 失败后自动重试次数（指数退避：500ms × 次数）。总执行次数 = 1 + retry |
 | `validate` | 否 | 无 | 输出校验：`json`（合法 JSON）、`json-array`（JSON 数组）、`non-empty`（非空）。校验失败视为失败并触发重试 |
 | `deliver` | 否 | 无 | 输出投递（v0.5.0）：`webhook:<url>` POST JSON，或 `file:<path>` 写入文件（自动建目录）。投递失败仅告警不阻塞 |

 ### 关于 output 参数

 如果指定了 `output`，模型回复会被存入变量，后面的块或正文可以用 `{{变量名}}` 引用。如果不指定，模型仍然会执行，但结果不会被保留到上下文中。通常建议始终指定 `output`，除非你只想测试连通性。

 ### 结构化输出（format）

 用 `format: "json"` 让模型回复自动 `JSON.parse` 后存入变量，下游模板可直接访问字段：

 ````markdown
 ```ai {output: "report", format: "json"}
 返回 JSON：{"summary": "...", "score": 0-100, "issues": [...]}
 {{data}}
 ```

 评分：{{report.score}}　问题数：{{report.issues | len}}
 ````

 - `format: "json"` 解析为对象；`format: "json-array"` 强制结果为数组（否则报错）
 - 解析失败时块失败，错误消息包含原始输出片段（截取前 200 字符）
 - 与 `stream: true` 兼容：先累积完整文本再解析
 - 与 `--cache` 兼容：缓存的 `value` 是解析后的对象而非字符串

 ### 外部 Prompt 库（prompt）

 v0.6.0 起支持 `.flow/prompts/<name>.md` 存放可复用的提示词模板，AI 块用 `prompt` 引用：

 ```bash
 # .flow/prompts/sales-analysis.md
 你是一个销售分析师。请基于以下数据分析{{topic}}：{{data}}
 输出格式要求：{{format}}
 ```

 ````markdown
 ```ai {output: "analysis", prompt: "sales-analysis", topic: "Q3 区域对比"}
 ```
 ````

 - `prompt` 与 inline 内容互斥，指定后以文件内容为提示词（未找到文件则报错）
 - 文件内 `{{变量}}` 照常渲染；非内容参数（如 `topic`）需通过 `--var` 或前置块注入
 - 与模板库（`.flow/templates/`）对称：模板管文档结构，prompt 库管 AI 提示词

 ### 多轮对话（conversation）

 v0.6.0 起同一 `conversation` 标签的 AI 块自动组成对话链，后块携带前序 user/assistant 历史：

 ````markdown
 ```ai {output: "analysis", conversation: "report"}
 分析这份财务报表...
 ```

 ```ai {output: "followup", conversation: "report"}
 基于上面的分析，风险点是什么？
 ```
 ````

 - 历史随执行进程保留在上下文；不同标签互不影响
 - 该块会自动把本轮 user 提示与 assistant 回复追加进历史
 - **带 `conversation` 的块跳过 `--cache`**（每次上下文不同，缓存无意义）

 ## 配置要求

 AI 块需要配置 LLM 提供商和 API Key。详见[配置指南](../02-configuration.md)。如果未配置 API Key，执行时会报错并提示设置环境变量。

 ## 命名模型预设

 如果文档中需要切换不同的模型或提供商，可以在配置文件中预定义多组命名模型预设，AI 块中按名称引用：

 ```yaml
 # .flow/config.yml
 llm:
   provider: openai
   model: gpt-4o
   models:
     fast:
       model: gpt-4o-mini
       temperature: 0.3
     reason:
       provider: openai
       model: deepseek-reasoner
       baseURL: https://api.deepseek.com
 ```

 ````markdown
 ```ai {model: "fast", output: "summary"}
 快速生成摘要
 ```

 ```ai {model: "reason", output: "analysis"}
 深度分析
 ```
 ````

 预设会覆盖全局 `llm` 配置的对应字段。如果预设切换了 `provider`，API Key 自动从对应的环境变量读取。

 ## 多模型组合使用

 结合命名模型预设，可以在同一个文档中调用不同提供商：

 ````markdown
 ```ai {model: "fast", output: "title"}
 生成一个标题
 ```

 ```ai {model: "reason", output: "content"}
 深入分析：{{title}}
 ```
 ````

 ## 变量注入

 执行时可通过命令行注入变量，AI 块内容中可直接引用：

 ```bash
 flowmd run doc.md --var topic=人工智能 --var style=正式
 ```

 ````markdown
 ```ai {output: "article"}
 请用{{style}}的风格写一篇关于{{topic}}的文章
 ```
 ````

 ## 系统变量

 以下系统变量自动注入到上下文，可在 AI 块内容中引用：

 - `{{date}}` — 当前日期（YYYY-MM-DD）
 - `{{datetime}}` — 当前日期时间（YYYY-MM-DD HH:mm:ss）
 - `{{timestamp}}` — 当前 Unix 时间戳

 ## 示例

 ### 基础用法

 ````markdown
 ```ai {output: "summary"}
 用一句话总结 FlowMD 的功能
 ```

 总结：{{summary}}
 ````

 ### 指定模型

 ````markdown
 ```ai {model: "gpt-4o-mini", output: "tags"}
 提取下面文本中的关键词：{{article}}
 ```
 ````

 ### 使用变量传递上下文

 AI 块的内容中可以引用之前块输出的变量：

 ````markdown
 ```data {output: "sales_data"}
 SELECT product, amount FROM orders
 ```

 ```ai {output: "analysis"}
 分析以下销售数据，指出趋势和异常：
 {{sales_data}}
 ```
 ````

 ### 链式调用

 多个 AI 块串联，后一个使用前一个的输出：

 ````markdown
 ```ai {output: "outline"}
 为"AI 在医疗领域的应用"生成一个大纲
 ```

 ```ai {output: "content"}
 根据以下大纲，扩展生成完整的文章：
 {{outline}}
 ```
 ````

 ### 低温度提取事实

 ````markdown
 ```ai {temperature: 0.1, output: "facts"}
 从以下文本中只提取事实信息，不添加任何评论：
 {{text}}
 ```
 ````

 ### 使用自定义 API 地址（代理或兼容 API）

 在配置中设置 `baseURL` 后，所有 AI 块都会使用该地址：

 ```bash
 export FLOW_LLM_BASE_URL="https://api.example.com/v1"
 ```

 这允许使用 Ollama、vLLM、DeepSeek 等兼容 OpenAI API 的服务。

 ## 最佳实践

 - **提示词要清晰**：写明角色、任务、输出格式、限制条件
 - **命名要有意义**：`summary` 比 `x` 可读性好得多
 - **拆解复杂任务**：多个链式 AI 块比一个超大提示词更稳定、更容易调试
 - **温度调低提取事实**：`temperature: 0.1` 适合信息提取，`0.8+` 适合创意生成
 - **多步工作流优先用模板块输出**：AI 回复是原始文本，适合用 template 块做最终排版
