 # AI 块

 ## 功能

 AI 块调用大语言模型（LLM）处理提示词，并将模型返回的结果存入变量上下文，供后续块或文档正文使用。

 当前支持两种提供商：

 - **OpenAI** — 兼容 OpenAI API 的服务（含 DeepSeek、Ollama 等兼容 API）
 - **Anthropic** — Claude 系列模型

 ## 语法

 ````markdown
 ```ai {model: "gpt-4o", output: "summary", temperature: 0.7}
 你的提示词，可以用 {{变量}} 引用上下文
 ```
 ````

 块的语言标识符必须为 `ai`，元数据用 JSON 风格的 `{key: value}` 写在语言标识符后面。

 ## 参数

 | 参数 | 必填 | 默认值 | 说明 |
 |------|------|--------|------|
 | `output` | 否 | 无 | 结果存入的变量名。不指定则只输出到终端（debug 模式） |
 | `model` | 否 | 配置文件的 `llm.model` | 覆盖默认模型，如 `gpt-4o-mini` |
 | `temperature` | 否 | 配置文件的 `llm.temperature` | 覆盖默认温度，0-1 |
 | `stream` | 否 | false | 流式输出，`true` 时 CLI spinner 实时显示生成内容（不影响最终结果） |

 ### 关于 output 参数

 如果指定了 `output`，模型回复会被存入变量，后面的块或正文可以用 `{{变量名}}` 引用。如果不指定，模型仍然会执行，但结果不会被保留到上下文中。通常建议始终指定 `output`，除非你只想测试连通性。

 ## 配置要求

 AI 块需要配置 LLM 提供商和 API Key。详见[配置指南](../02-configuration.md)。如果未配置 API Key，执行时会报错并提示设置环境变量。

 ## 命名模型预设

 如果文档中需要切换不同的模型或提供商，可以在配置文件中预定义多组命名模型预设，AI 块中按名称引用：

 ```yaml
 # .flow/config.yml
 llm:
   provider: openai
   model: gpt-4o
   models:
     fast:
       model: gpt-4o-mini
       temperature: 0.3
     reason:
       provider: openai
       model: deepseek-reasoner
       baseURL: https://api.deepseek.com
 ```

 ````markdown
 ```ai {model: "fast", output: "summary"}
 快速生成摘要
 ```

 ```ai {model: "reason", output: "analysis"}
 深度分析
 ```
 ````

 预设会覆盖全局 `llm` 配置的对应字段。如果预设切换了 `provider`，API Key 自动从对应的环境变量读取。

 ## 多模型组合使用

 结合命名模型预设，可以在同一个文档中调用不同提供商：

 ````markdown
 ```ai {model: "fast", output: "title"}
 生成一个标题
 ```

 ```ai {model: "reason", output: "content"}
 深入分析：{{title}}
 ```
 ````

 ## 变量注入

 执行时可通过命令行注入变量，AI 块内容中可直接引用：

 ```bash
 flowmd run doc.md --var topic=人工智能 --var style=正式
 ```

 ````markdown
 ```ai {output: "article"}
 请用{{style}}的风格写一篇关于{{topic}}的文章
 ```
 ````

 ## 系统变量

 以下系统变量自动注入到上下文，可在 AI 块内容中引用：

 - `{{date}}` — 当前日期（YYYY-MM-DD）
 - `{{datetime}}` — 当前日期时间（YYYY-MM-DD HH:mm:ss）
 - `{{timestamp}}` — 当前 Unix 时间戳

 ## 示例

 ### 基础用法

 ````markdown
 ```ai {output: "summary"}
 用一句话总结 FlowMD 的功能
 ```

 总结：{{summary}}
 ````

 ### 指定模型

 ````markdown
 ```ai {model: "gpt-4o-mini", output: "tags"}
 提取下面文本中的关键词：{{article}}
 ```
 ````

 ### 使用变量传递上下文

 AI 块的内容中可以引用之前块输出的变量：

 ````markdown
 ```data {output: "sales_data"}
 SELECT product, amount FROM orders
 ```

 ```ai {output: "analysis"}
 分析以下销售数据，指出趋势和异常：
 {{sales_data}}
 ```
 ````

 ### 链式调用

 多个 AI 块串联，后一个使用前一个的输出：

 ````markdown
 ```ai {output: "outline"}
 为"AI 在医疗领域的应用"生成一个大纲
 ```

 ```ai {output: "content"}
 根据以下大纲，扩展生成完整的文章：
 {{outline}}
 ```
 ````

 ### 低温度提取事实

 ````markdown
 ```ai {temperature: 0.1, output: "facts"}
 从以下文本中只提取事实信息，不添加任何评论：
 {{text}}
 ```
 ````

 ### 使用自定义 API 地址（代理或兼容 API）

 在配置中设置 `baseURL` 后，所有 AI 块都会使用该地址：

 ```bash
 export FLOW_LLM_BASE_URL="https://api.example.com/v1"
 ```

 这允许使用 Ollama、vLLM、DeepSeek 等兼容 OpenAI API 的服务。

 ## 最佳实践

 - **提示词要清晰**：写明角色、任务、输出格式、限制条件
 - **命名要有意义**：`summary` 比 `x` 可读性好得多
 - **拆解复杂任务**：多个链式 AI 块比一个超大提示词更稳定、更容易调试
 - **温度调低提取事实**：`temperature: 0.1` 适合信息提取，`0.8+` 适合创意生成
 - **多步工作流优先用模板块输出**：AI 回复是原始文本，适合用 template 块做最终排版
